# テストデータ

設計書4章の計算例を、計算のテストの入力と期待値にしたものです。テストは、ケースごとに入力を計算し、結果を期待値のファイルと比べます。

## フォルダの構成

```
tests/data/
  例01-04/            例のフォルダ
    基本/             ケースのフォルダ
      ケース.csv      ケースの出典と集計の条件
      入力/           3章のテーブルごとの CSV(9ファイル)
      入力.xlsx       「入力」フォルダの CSV と同じ中身のブック(例12・例13だけ)
      期待値/         4章の表ごとの CSV
```

- 例のフォルダは、設計書の例ごとに作り、「例05」のように2桁の番号を付ける。1つの節でまとめて計算する例(例1〜例4、例11A・例11B、例12A〜例12E、例13A〜例13G)は1つのフォルダにする(例1〜例4は「例01-04」)。共通の決まりの例は「共通の決まり」とする。
- ケースのフォルダは、入力か集計の条件が違うものごとに作る。設計書の表のとおりのものを「基本」とし、文中で入力や条件を変えたものは、変えた内容を名前にする(例:「集計基準日2027-04-01」)。例12は「条件1」〜「条件3」(集計の条件1〜3)、例14は「基本」と「変更01」〜「変更11」(表の#1〜#11)、例16は「基本」と「変更01」〜「変更07」(表の#1〜#7)とする。

## CSV の共通の決まり

- 文字コードは UTF-8(BOM付き)とし、1行目を列名にする。
- 日付は YYYY-MM-DD、年月は YYYY-MM で書く。
- 数は桁区切りを付けずに書く。文の中の数も同じ。
- 空欄は空の値とする。
- 真偽は「はい」「いいえ」で書く。

## ケース.csv

列は「項目」と「値」の2つです。

| 項目 | 値 |
| --- | --- |
| 出典 | 設計書のどこの値か。空欄にできない |
| 変更 | 「基本」から変えた内容 |
| 集計基準日 | 残予算と見込み残の集計基準日(YYYY-MM-DD) |
| 含める状態 | 山積みに含める状態。「、」で区切る |
| 費用区分 | 山積みに含める費用区分。「、」で区切る |

集計基準日・含める状態・費用区分は、その値を使う期待値があるケースにだけ書きます。集計の条件が設計書に書かれていない例5は、例1〜例4と同じく、集計基準日を2027-03-31、含める状態をすべてとします。

## 入力

- テーブルごとに1ファイルを置き、ファイル名はテーブル名にする(例:工事.csv)。行がないテーブルも、列名の行だけのファイルを置く。
- 列は3章の項目名と「削除済み」とし、3章の順に並べる。作成日時・作成者・更新日時・更新者は置かない。
- ID は、テーブルごとに1から、設計書に出てくる順に振る。「基本」から変えたケースでは、「基本」の ID を変えず、足した行に続きの ID を振る。
- 管理番号は例の名前(例1、例12A など。共通の決まりの例は「共通の決まり」)とする。期待値の「例」の列は、この管理番号で工事と結び付く。
- 作業日数は小数点以下1桁まで書く(例:10.5、12.0)。
- 予算年割には、設計書に書かれた年割の値を入れる。「年割は初期値のまま」の例では、その初期値を入れる。
- 設計書に書かれていない必須の項目は、次の値にする。

| 項目 | 値 |
| --- | --- |
| 工事名 | 管理番号と同じ |
| 工事の状態 | 計画中 |
| 費用内訳の費用区分 | 修繕費 |
| 費用内訳の計上の考え方 | 出来高 |
| 例1〜例5の人員区分の区分名 | 一般(直営・一般、協力会社・一般) |
| 人員区分の使用中 | はい |
| 人員区分の表示順 | ID と同じ |
| 削除済み | いいえ |

## 入力のブック

例12と例13の各ケース(例12の「条件1」〜「条件3」、例13の「基本」「例13Gを追加」「集計基準日2028-04-01」の6つ)には、ケースのフォルダに「入力.xlsx」を置きます。中身は、同じケースの「入力」フォルダの CSV と同じです。ブックから読んでも CSV から読んでも、同じテーブルになります。ほかの例のケースには置きません。

- テーブルごとに1枚のシートを置き、シート名はテーブル名にする。シートはテーブルの順(工事・費用内訳・予算年割・実績・月別修正・作業明細・人員区分・単価・予算枠)に並べる。
- 1行目を列名にする。列は CSV と同じ順に置き、2行目から CSV の行を同じ順に置く。行がないテーブルは、列名の行だけにする。
- 列名の行のセルは、文字のセル(書式は標準)にする。
- 値のセルの型と書式は、列の型(設計書3章の項目の型)で決める。

| 列の型 | セル | 書式 |
| --- | --- | --- |
| 整数・金額・年度・小数(作業日数) | 数値のセル。CSV の数をそのまま入れる(作業日数の 3.0 は 3 になる) | 標準 |
| 日付 | 日付のセル(時刻は0) | yyyy-mm-dd |
| 年月 | その月の1日の日付のセル(時刻は0) | yyyy-mm |
| 文字列・長文(管理番号・工事名・区分名など) | 文字のセル | 文字(@)。値が空欄のセルも文字にする |
| 選択・真偽(削除済みを含む) | 文字のセル | 標準 |

- 空欄は、値のない空のセルにする。

### ブックの作り方

ブックは手で作らず、テストの側の処理(tests/MaintPlan.Tests/Support/InputWorkbooks.cs)で「入力」フォルダの CSV から作り、それをリポジトリに入れます。CSV を直したときは、ブックも作り直してコミットします。作り直すには、リポジトリのフォルダで、環境変数 MAINTPLAN_WRITE_INPUT_WORKBOOKS を 1 にして `dotnet test` を動かします。

```
# bash
MAINTPLAN_WRITE_INPUT_WORKBOOKS=1 dotnet test

# PowerShell
$env:MAINTPLAN_WRITE_INPUT_WORKBOOKS = "1"; dotnet test; Remove-Item Env:MAINTPLAN_WRITE_INPUT_WORKBOOKS
```

- このとき、InputWorkbookTests の Rewrite_input_workbooks_in_the_source_tree が、リポジトリの tests/data にある6冊を作り直す(出力のフォルダにある写しではない)。環境変数がないときは、このテストはスキップになる。
- 作り直した回は、出力のフォルダにある古いブックと比べるテストが失敗することがある。環境変数なしでもう一度 `dotnet test` を動かし、すべて成功することを確かめる。
- Excel で開いて保存し直したブックは、コミットしない。確かめた後は、元に戻す。

### 確かめていること

InputWorkbookTests で、例12・例13の各ケースについて、次を確かめます。

- 置いたブックのセル(シート名と、値か書式のあるセルの値・型・書式)が、今の「入力」フォルダの CSV から作ったブックと同じ。ファイルのバイトは、作るたびに作成日時などが変わるので比べない。
- セルの型と書式が、上の表のとおり。
- ブックから読んだ9つのテーブルが、「入力」フォルダの CSV から読んだものと同じ。

## 期待値

設計書4章の表ごとに1ファイルを置きます。表の列名・行・値の書き方をそのまま写し、数の桁区切りだけを外します。「未入力」「0(未登録)」「出さない」など、表の中の文もそのまま書きます。

- 列名に集計の条件が入っている表(例:「欄(費用区分は両方)」)は、列名を「欄」とし、条件はケース.csv に書く。
- 文中に書かれた値は、下の種類のうち近い形の表にし、ファイル名の最後に「_一部」を付ける。
- 値の列は、設計書に値が書かれているものだけを置く。値が書かれていないセルは空欄にする。
- 設計書が「ほかの行は変わりません」「予算枠・実績額・残予算は変わりません」のように変わらないと書いた値は、もとの表の値を写す。

### 比べ方

- 「_一部」が付かないファイルは、表にない行の値をすべて0として比べる。
- 「_一部」が付くファイルは、書いた行だけを比べる。
- どちらも、空欄のセルは比べない。
- 金額は整数として、人工は数として比べる(「0」と「0.0」は同じ)。それ以外は文字のまま比べる。

### キーの列

| 列 | 値 |
| --- | --- |
| 例 | 工事の管理番号。設計書の表にない場合(工事が1件の例)は置かない |
| 費用内訳 | 費用内訳の費用区分(修繕費・設備投資)。設計書の表にない場合は置かない |
| 人員区分 | 「直営」「協力会社」は種別ごとの合計。「直営・機械」のように区分名まで書いたものは区分ごとの値。種別ごとの行の単価は、その行にまとめた単価がすべて同じときの値 |
| 行 | 作業明細の ID |

労務費の内訳には、予算額の計算に含めない区分の作業明細の行は置きません(計算結果にも出さない)。

「例」「費用内訳」の列を置かない表は、その列の値で分けずに合計した値と比べます。

### 期待値の種類

| ファイル名 | キーの列 | 値の列 |
| --- | --- | --- |
| 月ごとの日数 | 年月 | 日数 |
| 月ごとの値 | (例)、(費用内訳)、年月 | 予算額、見積額、実績額、人工 |
| 人工の月ごとの内訳 | (例)、(費用内訳)、人員区分か行、年月 | 人工 |
| 計算に使わない修正 | (例)、費用内訳、金額の種類、年月 | 金額、理由 |
| 予算額の初期値 | (例)、(費用内訳) | 労務費、予算額の初期値、年割の初期値、知らせる内容 |
| 労務費の内訳 | (例)、(費用内訳)、人員区分か行、年度 | 人工、単価、労務費 |
| 山積み | 欄 | 予算額、見積額、実績額、人工 |
| 人工の内訳 | 欄、人員区分 | 人工 |
| 未入力の件数 | 金額の種類 | 件数、対象 |
| 残予算と見込み残 | 年度・費用区分 | 予算枠、実績額、残予算、未実績見込み、見込み残 |
| 未実績見込みの内訳 | (例)、(費用内訳)、年度 | 年度配分、未実績見込み |
| 保存の確認 | なし | 保存できる、理由の種類 |

括弧の列は省けます。保存の確認には、設計書の文を写した「結果」の列も置きます。この列は比べません。

### 値の書き方

| 列 | 書き方 |
| --- | --- |
| 年月(月ごとの日数) | YYYY-MM、「合計」 |
| 年月(そのほか) | YYYY-MM、「YYYY年度 時期未定」、「年度のない時期未定」 |
| 年度 | 「YYYY年度」。労務費の内訳では「合計」も使う |
| 欄 | 「YYYY年度 1Q」〜「YYYY年度 4Q」、「YYYY年度 時期未定」、「YYYY年度 合計」、「年度のない時期未定」 |
| 年度・費用区分 | 「2026年度 修繕費」の形 |
| 人工 | 小数点以下1桁(例:8.7、0.0)。設計書の表で「0」と書かれたものは「0」のまま |
| 年割の初期値 | 「2026年度 1603076、2027年度 1731324」の形 |
| 対象 | 例の名前を「、」でつなぐ |
| 理由 | 工期に入らない月、完成工事高の費用内訳 |
| 理由の種類 | 作業明細の期間が工期の外、工事の日付が空欄で作業明細に日付がある、見積額の修正の合計が見積額を超える、見積額の全部の月の修正の合計が見積額と一致しない、予算額の修正の合計が年割額を超える、予算額の全部の月の修正の合計が年割額と一致しない。理由が2つ以上あるときは、重複なしでこの順に「、」でつなぐ。 |
