## 確認済みの決まり

テストデータを作るときと、各段の実装で決めたもので、利用者の確認を受けたものです。

テストデータ(段1)

1. 例14の「理由の種類」の名前(README の「値の書き方」)。工事の日付が空欄で作業明細に日付があるとき(例14の変更02)は、「工事の日付が空欄で作業明細に日付がある」だけを出す。
2. 労務費の内訳には、予算額の計算に含めない区分の作業明細の行を出さない(例10の3行目)。
3. 設計書に書かれていない値:工事名は管理番号と同じ、状態は計画中、費用区分は修繕費、計上の考え方は出来高、例1〜例5の人員区分の区分名は「一般」、例5の集計基準日は2027-03-31で含める状態はすべて。

月への割り振り(段2)

1. 工事の日付が空欄の、出来高の費用内訳にある月別修正は、計算に使わず「工期に入らない月」として知らせる。
2. 完成工事高の費用内訳の、工期外の月の修正は、理由「完成工事高の費用内訳」の1件だけ知らせる。
3. 年割がない年度の予算額の修正と、見積額が空欄の費用内訳の見積額の修正は、計算に使わず、知らせる一覧にも出さない。
4. 「例」「費用内訳」の列を省いて複数の費用内訳を1行に合計する表では、行に当たる費用内訳がすべて未入力なら「未入力」、1件でも入力があれば入力済みの分の合計を書く。
5. 削除済みの人員区分を参照する、削除されていない作業明細は、人工の割り振りに含める。
6. 負の金額は、C# の整数の割り算の商(0の方向への切り捨て)をそのまま使う。
7. 全部の月を修正し、合計が見積額・年割額と一致しないときは、計算を止めずに修正の金額だけを使う。
8. 開始日と終了日の片方だけ、終了日が開始日より前、月別修正・年割の重複、月別修正の金額の種類が実績額は、対象の ID を入れた InvalidOperationException にする。

予算額の初期値(段3)

1. 労務費の内訳の「合計」の行は、人員区分の列がある表にだけ置き、労務費だけを書く。行の列の表には置かない。
2. 単価が足りないかを確かめる年度は、作業明細の行の期間が1日でもかかる年度(工事の日付が空欄なら実施年度)。予算額の計算に含める区分だけを確かめる。
3. 知らせる内容は「足りない単価:直営・電気の2028年度、協力会社・一般の2028年度」の形で、種別・表示順・年度の順に「、」でつなぐ。知らせることがなければ「なし」。
4. 初期値を出さない費用内訳は、労務費と年割の初期値を空欄にし、労務費の内訳の行も出さない。
5. 「例」「費用内訳」の列を省いて複数の費用内訳を1行に合計する表では、労務費・初期値・年割を合計する。1件でも初期値を出さないものがあれば「出さない」とし、知らせる内容はつなぐ。
6. 削除済みの単価は使わず、足りない単価として扱う。削除済みの人員区分の「予算額の計算に含める」はそのまま使う。同じ人員区分・年度の単価が重複したら InvalidOperationException にする。
7. 種別ごとの行(「直営」など)の単価は、その行にまとめた単価がすべて同じときだけ書き、違うときは空欄にする。

山積みの集計(段4)

1. 年度の合計と、人工の直営・協力会社の別の内訳は、Core の結果(`AggregationResult`)に入れる。欄の種類に年度の合計(`AggregationColumnKind.FiscalYearTotal`)があり、人工の内訳は `StaffCategoryId` が空なら種別ごとの合計。`ResultTables` は文字にするだけとする。
2. 山積みと人工の内訳の表には、金額か人工の値が1件でも入った欄(合計が0でも出す)と、その年度の合計の行を出す。値が1件も入らない欄の行は出さない。
3. 人工の内訳にも「YYYY年度 合計」の行を置く。
4. 未入力の件数は費用内訳の数で数える。対象は、その費用内訳の工事の管理番号を、工事 ID の順に重複なしで「、」でつなぐ。予算額・見積額は0件でも1行出し(対象は空欄)、実績額の行は出さない。
5. 含める状態か費用区分が空なら、そのまま計算する(欄はすべて0、未入力は0件)。

残予算と見込み残(段5)

1. 結果の型は `RemainingBudgetRow`・`UnrealizedEntry` のまま使い、計算は Core、`ResultTables` は文字にするだけとする。
2. 予算枠が未登録の年度・費用区分の行は、その年度・費用区分の実績額の合計か未実績見込みが0でないときだけ出す。登録済みの予算枠の行は、実績額も未実績見込みも0でも出す。
3. 実績額の合計が0以下なら、年度配分から差し引かない。年度配分が0以下の年度は飛ばして次の年度から差し引き、その年度の未実績見込みは年度配分のままとする。
4. 未実績見込みの内訳(発注済み・施工中の費用内訳だけ)には、年度配分が入った年度(0でも)と、0でない額を移した先の年度に行を出す。移す額が0なら、移した先の行は出さない。

保存できない条件の確認(段6)

1. 保存できない理由が2件以上あるとき、保存の確認の表は1行とし、理由の種類を重複なしで README の「理由の種類」の順に「、」でつなぐ。Core の結果(`SaveValidationResult`)には、違反をすべて入れる。
2. 全部の月を修正し、その合計が見積額(予算額は年割額)を超えるときは、「修正の合計が…を超える」だけを出し、「全部の月の修正の合計が…と一致しない」は出さない。
3. 月別修正は、月への割り振りで計算に使うものだけを数える。工期に入らない月の修正(工事の日付が空欄なら、すべての修正)、完成工事高の費用内訳の修正に加えて、年割がない年度の予算額の修正と、見積額が空欄の費用内訳の見積額の修正も数えない。

## 確認を受けていない決まり

段4〜段6の実装で、設計書から決めたものです。利用者の明示の確認はまだです。

段4

1. 状態と費用区分の条件は、実績額にも当てる(4章の集計の条件の表による。条件で外れる工事に実績がある例はなく、期待値では縛られていない)。
2. `ResultTables.Aggregation` は、列にある金額の種類の結果が渡されないときと、金額の種類ごとの結果で人工が食い違うとき(集計の条件の違う結果を渡したとき)に ArgumentException にする。

段5

1. 「実績額の合計が見積額以上なら、未実績見込みは0」の見積額は、費用内訳の見積額の項目と比べる。全部の月を修正して合計が見積額と合わない費用内訳(保存できないデータ)では、年度配分の合計とは比べない。
2. 集計基準日より後の月の実績額も、残予算と未実績見込みの実績額の合計に入れる(設計書で集計基準日を使うのは、時期未定の年度配分の年度と、移す先の年度を決めるときだけのため)。
3. 削除済みでない予算枠が同じ年度・費用区分で重複したら、InvalidOperationException にする(段2・段3の重複の扱いに合わせる)。削除済みの予算枠は未登録として扱う。

段6

1. 保存の確認でも、開始日と終了日の片方だけ、終了日が開始日より前、月別修正・年割の重複、月別修正の金額の種類が実績額は、段2と同じく対象の ID を入れた InvalidOperationException にする(段2の確認済みの決まり8に合わせる)。

## 環境

- .NET 10 SDK が入っていないコンテナでは、セッションの最初に `apt-get install -y dotnet-sdk-10.0` で入れる(Ubuntu のパッケージ。10.0.112 で動作を確認)。`dotnet --version` で入っているかを確かめる。
- NuGet の検索サービスはプロキシで止められている。そのため `dotnet new install <パッケージ名>` は使えない。テンプレートが要るときは、api.nuget.org から nupkg を直接取得して `dotnet new install <ファイル>` で入れる。パッケージの復元は通る。
- テストは `dotnet test` で、Microsoft Testing Platform で動く(global.json で指定)。
- GitHub の操作は MCP のツールで行う(gh コマンドは使えない)。
