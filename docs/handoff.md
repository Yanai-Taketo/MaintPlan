## 確認済みの決まり

テストデータを作るときと、各段の実装で決めたもので、利用者の確認を受けたものです。

テストデータ(段1)

1. 例14の「理由の種類」の名前(README の「値の書き方」)。工事の日付が空欄で作業明細に日付があるとき(例14の変更02)は、「工事の日付が空欄で作業明細に日付がある」だけを出す。
2. 労務費の内訳には、予算額の計算に含めない区分の作業明細の行を出さない(例10の3行目)。
3. 設計書に書かれていない値:工事名は管理番号と同じ、状態は計画中、費用区分は修繕費、計上の考え方は出来高、例1〜例5の人員区分の区分名は「一般」、例5の集計基準日は2027-03-31で含める状態はすべて。

月への割り振り(段2)

1. 工事の日付が空欄の、出来高の費用内訳にある月別修正は、計算に使わず「工期に入らない月」として知らせる。
2. 完成工事高の費用内訳の、工期外の月の修正は、理由「完成工事高の費用内訳」の1件だけ知らせる。
3. 年割がない年度の予算額の修正と、見積額が空欄の費用内訳の見積額の修正は、計算に使わず、知らせる一覧にも出さない。ただし、工期に入らない月の修正と、完成工事高の費用内訳の修正は、見積額が空欄でも年割がなくても、それぞれ「工期に入らない月」「完成工事高の費用内訳」として知らせる。知らせるのは、見積額や年割額を入れても使われない修正だけとする。
4. 「例」「費用内訳」の列を省いて複数の費用内訳を1行に合計する表では、行に当たる費用内訳がすべて未入力なら「未入力」、1件でも入力があれば入力済みの分の合計を書く。
5. 削除済みの人員区分を参照する、削除されていない作業明細は、人工の割り振りに含める。
6. 負の金額は、C# の整数の割り算の商(0の方向への切り捨て)をそのまま使う。
7. 全部の月を修正し、合計が見積額・年割額と一致しないときは、計算を止めずに修正の金額だけを使う。
8. 開始日と終了日の片方だけ、終了日が開始日より前、月別修正・年割の重複、月別修正の金額の種類が実績額は、対象の ID を入れた InvalidOperationException にする。

予算額の初期値(段3)

1. 労務費の内訳の「合計」の行は、人員区分の列がある表にだけ置き、労務費だけを書く。行の列の表には置かない。
2. 単価が足りないかを確かめる年度は、作業明細の行の期間が1日でもかかる年度(工事の日付が空欄なら実施年度)。予算額の計算に含める区分だけを確かめる。
3. 知らせる内容は「足りない単価:直営・電気の2028年度、協力会社・一般の2028年度」の形で、種別・表示順・年度の順に「、」でつなぐ。知らせることがなければ「なし」。
4. 初期値を出さない費用内訳は、労務費と年割の初期値を空欄にし、労務費の内訳の行も出さない。
5. 「例」「費用内訳」の列を省いて複数の費用内訳を1行に合計する表では、労務費・初期値・年割を合計する。1件でも初期値を出さないものがあれば「出さない」とし、知らせる内容はつなぐ。
6. 削除済みの単価は使わず、足りない単価として扱う。削除済みの人員区分の「予算額の計算に含める」はそのまま使う。同じ人員区分・年度の単価が重複したら InvalidOperationException にする。
7. 種別ごとの行(「直営」など)の単価は、その行にまとめた単価がすべて同じときだけ書き、違うときは空欄にする。

山積みの集計(段4)

1. 年度の合計と、人工の直営・協力会社の別の内訳は、Core の結果(`AggregationResult`)に入れる。欄の種類に年度の合計(`AggregationColumnKind.FiscalYearTotal`)があり、人工の内訳は `StaffCategoryId` が空なら種別ごとの合計。`ResultTables` は文字にするだけとする。
2. 山積みと人工の内訳の表には、金額か人工の値が1件でも入った欄(合計が0でも出す)と、その年度の合計の行を出す。値が1件も入らない欄の行は出さない。
3. 人工の内訳にも「YYYY年度 合計」の行を置く。
4. 未入力の件数は費用内訳の数で数える。対象は、その費用内訳の工事の管理番号を、工事 ID の順に重複なしで「、」でつなぐ。予算額・見積額は0件でも1行出し(対象は空欄)、実績額の行は出さない。
5. 含める状態か費用区分が空なら、そのまま計算する(欄はすべて0、未入力は0件)。
6. 状態と費用区分の条件は、実績額にも当てる。状態を絞った山積みの実績額は、残予算の表の実績額(状態によらない)と合わなくてよい。
7. `ResultTables.Aggregation` は、列にある金額の種類の結果が渡されないときと、金額の種類ごとの結果で人工が食い違うとき(集計の条件の違う結果を渡したとき)に ArgumentException にする。

残予算と見込み残(段5)

1. 結果の型は `RemainingBudgetRow`・`UnrealizedEntry` のまま使い、計算は Core、`ResultTables` は文字にするだけとする。
2. 予算枠が未登録の年度・費用区分の行は、その年度・費用区分の実績額の合計か未実績見込みが0でないときだけ出す。登録済みの予算枠の行は、実績額も未実績見込みも0でも出す。
3. 実績額の合計が0以下なら、年度配分から差し引かない。年度配分が0以下の年度は飛ばして次の年度から差し引き、その年度の未実績見込みは年度配分のままとする。
4. 未実績見込みの内訳(発注済み・施工中の費用内訳だけ)には、年度配分が入った年度(0でも)と、0でない額を移した先の年度に行を出す。移す額が0なら、移した先の行は出さない。
5. 「実績額の合計が見積額以上なら、未実績見込みは0」の見積額は、費用内訳の見積額の項目と比べる。全部の月を修正して合計が見積額と合わない費用内訳(保存できないデータ)でも、年度配分の合計とは比べない。
6. 集計基準日より後の月の実績額も、残予算と未実績見込みの実績額の合計に入れる。集計基準日は、時期未定の年度配分の年度と、前の年度の残りを移す先の年度を決めるときだけに使い、その日の時点の締めには使わない。
7. 削除済みでない予算枠が同じ年度・費用区分で重複したら、InvalidOperationException にする。削除済みの予算枠は未登録として扱う。

保存できない条件の確認(段6)

1. 保存できない理由が2件以上あるとき、保存の確認の表は1行とし、理由の種類を重複なしで README の「理由の種類」の順に「、」でつなぐ。Core の結果(`SaveValidationResult`)には、違反をすべて入れる。
2. 全部の月を修正し、その合計が見積額(予算額は年割額)を超えるときは、「修正の合計が…を超える」だけを出し、「全部の月の修正の合計が…と一致しない」は出さない。
3. 月別修正は、月への割り振りで計算に使うものだけを数える。工期に入らない月の修正(工事の日付が空欄なら、すべての修正)、完成工事高の費用内訳の修正に加えて、年割がない年度の予算額の修正と、見積額が空欄の費用内訳の見積額の修正も数えない。
4. 保存できない理由には、年度(予算額の理由)と、比べた2つの金額(修正の合計と、見積額か年割額)を持たせる。
5. 保存の確認でも、開始日と終了日の片方だけ、終了日が開始日より前、月別修正・年割の重複、月別修正の金額の種類が実績額は、段2と同じく対象の ID を入れた InvalidOperationException にする(段2の確認済みの決まり8に合わせる)。

読み込み時の確認(段7 sub2)

1. 違反があるときは、表を書き出さずに止め、違反の一覧を画面に出す(終了コード1)。
2. 違反はすべて示す。形(型・必須・選択値)の誤りがあればそれをすべて示して止め、重複・参照先・保存できない条件は、形の誤りがないときだけ確かめる。
3. 行は、CSV はファイルの行番号(列名の行が1行目)で示す。重複は2件目以降の行で示し、文に最初の行を書く。
4. ID・管理番号の重複と参照先は、削除済みの行も含めて確かめる。そのほか(組み合わせの重複、工事番号の重複、工事と作業明細の日付、月別修正の金額の種類、保存できない条件)は、削除済みの行と、削除済みの工事・費用内訳の下にある行を確かめない(計算と同じ)。人員区分が削除済みでも、その単価は確かめる(計算で使うため)。
5. ID の重複は違反にする。
6. 参照先の行がなければ違反にする。削除済みの行を参照する行は違反にしない。
7. 終了日が開始日より前は、行で示す。
8. 3章の重複なし(管理番号、工事ID と費用区分、工事番号、種別と区分名、費用内訳ID と年度、費用内訳ID・金額の種類・年月、人員区分ID と年度、年度と費用区分)を確かめる。
9. 設計書が決めていない点(文字数の上限、日付と実施年度の両方が入った工事、費用内訳が0件の工事、金額の負の値、前後の空白)は確かめない。
10. 保存できない条件は、作業明細の理由を作業明細の行、見積額の理由を費用内訳の行、予算額の理由をその年度の予算年割の行で示す。
11. 計算に使わない修正(工期に入らない月など)は違反にせず、今のとおり「計算に使わない修正」の表に出す。
12. 違反は画面だけに出し、ファイルには書かない。
13. 読み込み時の違反のテストは、テストの中で入力を作り、3章の決まりから手で決めた行と理由を書く。保存できない条件は例14の11件と例16の7件を使う。
14. `ResultTables.Aggregation` の確認は、結果に集計の条件を持たせ、状態と費用区分が同じかを比べる。
15. 保存できない条件は、保存の確認が例外になる行と、どの行を指すかが決まらない行だけを除いて確かめる。除くのは、工事・費用内訳・作業明細の ID が重複した行(最初の行も)、工事と作業明細の日付が決まりに合わない行、費用内訳と年度が重複した年割の行(最初の行も)、金額の種類が決まりに合わない月別修正の行、組み合わせが重複した月別修正と費用内訳・金額の種類が同じ修正すべて(修正の合計が決まらないため)。管理番号・工事番号などの重複や参照先の違反では、行を除かない。
16. 形の誤りは、1行に2つ以上あれば列ごとに示す。ファイルがないテーブルと、列名に過不足があるテーブルは、行を読まない。列の数が列名の行と合わない行や、閉じない引用符など CSV の形の誤りは、そのファイルで1件として示し、そのファイルの残りの行は読まない。
17. 月別修正の金額の種類は、予算額と見積額だけを受け付け、ほかの値は「「実績額」は予算額・見積額のどれかではありません。」の形で示す。Core の入力の確認でも、金額の種類を確かめる(CSV 以外から読んだときのため。確かめない行は決まり4のとおり)。
18. 画面の見出しは、形の誤りが「読み込めません」、3章の決まりと参照先が「決まりに合いません」、4章の保存できない条件が「保存できません」。最後に「N件の誤りがあるため、表を書き出していません。」と出す。
19. 理由の文は「工事.csv 6行目 列「ID」: ID 1 が重複しています。最初の行は2行目です。」「予算年割.csv 2行目 列「予算額」: 2027年度の予算額の修正の合計 1,000,000 が、年割額 900,000 を超えています。」の形とする。理由の文の金額は、設計書4章の例14の文に合わせて桁区切りを付ける。列が2つ以上なら「列「開始日」「終了日」」と並べる。
20. 示す列は、作業明細の理由が「開始日」「終了日」、見積額の理由が「見積額」、予算額の理由が「予算額」、組み合わせの重複がその組み合わせの列。
21. `ResultTables.Aggregation` と `MissingAmounts` は、結果の金額の種類が辞書のキーと違うときと、状態・費用区分が違うときに ArgumentException にする。人工が食い違うとき(違う入力から集計した結果を渡したとき)の ArgumentException は残す。`QuarterlyAggregation.Calculate` は、条件の集合の写しを結果に持たせ、呼び出し側が後で集合を変えても結果の条件は変わらない。
22. 整数の列(ID・参照の ID・人数・表示順)と作業日数は、0以上だけを受け付ける。負の値は形の誤りとし、「「-2」は0以上の整数ではありません。」「「-1.5」は0以上の、小数点以下1桁までの数ではありません。」の形で示す。人数・作業日数・表示順が0以上であることは、設計書3章の決まり。
23. 削除済みの工事・費用内訳の下にあるかは、同じ ID の行で決める。工事は、同じ ID の行がすべて削除済みのときだけ削除済みとする。費用内訳は、削除済みの印があるか工事が削除済みの行を削除済みとして扱い、同じ ID の行がすべてそうなら削除済みとする(計算の対象の決め方と同じ)。参照先の行がない行は、削除済みの親の下とは扱わず、確かめる。

Excel の読み書き(段7 sub3)

1. 読むのは .xlsx のブックだけ。`--input` がフォルダなら CSV、拡張子が .xlsx のファイルならブックとして読む。ほかは引数の誤り(終了コード2)とする。
2. ブックは、9つのテーブルと同じ名前のシートを読む。ほかのシートは読まない。1行目を列名とする。テーブルのシートがないとき、列名に過不足があるとき、列名が重複するときは、CSV と同じく形の誤りとする。
3. 値のあるセルが1つもない行は読まない。
4. 行は、Excel の行番号(列名の行が1行目)で示す。文の場所は「シート「工事」 6行目 列「ID」」の形とし、続く文は CSV と同じにする。
5. 文字のセルは、CSV と同じ決まりと同じ文で読む。空のセルと、空の文字のセルは空欄とする。
6. 文字のほかに受け付けるセルは、列ごとに次のとおりとする。
   - 整数(ID・参照の ID・人数・表示順)・年度・金額:数値のセルで、15桁に丸めた値が整数のもの
   - 作業日数:数値のセルで、15桁に丸めた値が小数点以下1桁までのもの
   - 日付:日付のセルで、時刻が0のもの
   - 年月:日付のセルで、1日、時刻が0のもの
   - 文字(管理番号・工事名・工事番号・区分名など):数値のセルで、15桁に丸めた値が整数のもの。その数字を文字として読む(例:123456 は「123456」)
   - 真偽・選択項目:文字のセルだけ
7. 数式のセルは形の誤りとし、「数式のセルは読みません。値で貼り付けてください。」と示す。
8. 次のセルは、形の誤りとする。値は Excel で表示される文字で示す(例:「「46113」は YYYY-MM-DD の日付ではありません。」)。
   - 列に合わない型のセル(日付の列の数値のセル、真偽のセル、エラーのセルなど)
   - 時刻のある日付のセル
   - 年月の列にある、1日でない日付のセル
9. 数値のセルは、15桁に丸めてから読む。丸めたあとの絶対値が10の15乗以上の数は形の誤りとし、「16桁以上の数は、文字のセルで入れてください。」と示す。
10. `--output` の末尾が .xlsx なら、結果をブック1冊に書き出す。それ以外は、今のとおり CSV のフォルダに書き出す。
11. 結果のブックは、表ごとのシート(シート名は表の名前)に、1行目を列名として書く。列は CSV と同じ。セルの型は次のとおりとし、表示の書式は付けない。
    - 数値のセルにする列:月ごとの値と山積みの予算額・見積額・実績額・人工、予算額の初期値の労務費・予算額の初期値、人工の内訳の人工、残予算と見込み残の予算枠・実績額・残予算・未実績見込み・見込み残、計算に使わない修正の金額
    - これらの列でも、値が文字(「未入力」「出さない」など)のときと、有効数字が15桁を超えるときは、文字のセルにする
    - ほかの列は、文字のセルにする
12. 結果のブックは作り直して上書きする(ブックのほかのシートは残らない)。出力先の親のフォルダがなければ作る。開いているかの確認と、同じ名前のフォルダの確認は、CSV のファイルと同じにする。
13. ClosedXML は 0.105.1 を使う。版は、Directory.Packages.props の `Version="0.105.1"` と、ロックファイル(packages.lock.json)で固定する。
14. 例12・例13の各ケースのフォルダに、「入力」フォルダの CSV と同じ中身の「入力.xlsx」を置く(6冊)。セルは次のとおりとする。ブックの中身が CSV と同じことは、テストで確かめる。
    - 数:数値のセル
    - 日付:日付のセル(書式 yyyy-mm-dd)
    - 年月:1日の日付のセル(書式 yyyy-mm)
    - ほかの値:文字のセル。文字の列は、セルの書式を文字にする

## 既知の制約

設計書が決めておらず、直さないことにしたものです。

1. 月別修正の合計が long の範囲を超える入力は、読み込み時の確認で、違反の一覧を出さずに「計算できません: 金額か人工が大きすぎます。」で止まる。9999年度の年割など、年度の翌年の日付が要る入力は、.NET の英語のメッセージ(「計算できません: 」に続く文)で止まる。どちらも実際のデータでは起きない値なので、直さない。年度と金額の範囲は、画面の入力の決まりを決めるときに決める。
2. CSV のセルの中に CR だけの改行があるときと、閉じない引用符があるときは、形の誤りで示す行がずれる。ファイルは正しく示し、そのファイルの残りの行は読まない。

## 環境

- .NET 10 SDK が入っていないコンテナでは、セッションの最初に `apt-get install -y dotnet-sdk-10.0` で入れる(Ubuntu のパッケージ。10.0.112 で動作を確認)。`dotnet --version` で入っているかを確かめる。
- NuGet の検索サービスはプロキシで止められている。そのため `dotnet new install <パッケージ名>` は使えない。テンプレートが要るときは、api.nuget.org から nupkg を直接取得して `dotnet new install <ファイル>` で入れる。パッケージの復元は通る。
- テストは `dotnet test` で、Microsoft Testing Platform で動く(global.json で指定)。
- GitHub の操作は MCP のツールで行う(gh コマンドは使えない)。
